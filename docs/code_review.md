# 本轮代码复查与整理

复查范围是当前 SmolVLM V/P/D 主线、共享 HTTP/进程基础设施、单体对照与验收脚本。
上游 vLLM 大模型路径和简历项目 1 不在本轮代码验证范围内。

## 修正与简化

| 问题 | 本轮处理 |
|---|---|
| HTTP 与运行时重复 Base64 解码和图片验证 | 入口生成 `PreparedVPDRequest`，HTTP 与直接调用共用 `prepare` / `run_prepared`；单体对照使用相同边界 |
| 用虚构的单 Token 检查生成长度，混合了两个职责 | 单独提取 `validate_generation`；真实 prompt 展开后再检查上下文与 KV 预算 |
| KV 布局函数再次执行已完成的请求预算检查 | `cache_shape` 只计算布局；接收边界保留 `validate_header` 的身份与预算检查 |
| NCCL 已完成接收后，同设备 stage 再同步一次 | 同设备直接返回，跨设备搬运才同步；接收完成与 ACK 约束保留 |
| 视觉编码函数掺入 Gloo/NCCL 设备选择 | 编码负责特征与计时，通信设备转换统一交给 `TensorChannel.prepare` |
| 每次请求重复读模型 JSON、计算配置签名 | 配置和在线签名缓存为实例快照；模型构造器拿副本，避免补写字段污染快照 |
| 请求超时短于启动超时，可能提前打断通信初始化 | 通信组超时取二者较大值；主进程仍分别限制启动和单请求截止时间 |
| 探针先报告成功，退出失败仍可能误报通过 | 通信组销毁后再报告，父进程检查最终退出码；异常退出不能算验收通过 |

没有为当前规模增加新的调度框架、恢复状态机或传输后端。`LocalVPD` 继续复用 `LocalPD`
的进程、事件收集和整组回收机制；`TensorChannel` 只处理载荷，控制帧函数继续共享。

## 为什么仍保留这些检查

- 输入入口：限制消息、图片、生成长度，保证错误能在 SSE 开始前返回。
- 接收边界：核对请求/模型/上下文与形状，并在分配前检查预算，避免串请求和不受控分配。
- 数据所有权：等待通信完成、设备就绪与 ACK，避免发送端提前释放仍在使用的存储。
- 运行时边界：监督进程、截止时间和回调失败；半次交接无法安全重试时整组停止。

这些检查承担不同职责。删掉重复检查不等于删掉边界约束。

## 验证

新增回归覆盖：原始消息变更不影响准备好的请求、HTTP 流式/非流式各验证图片一次、
无效流式请求在 SSE 头前返回 413、配置快照不随磁盘 JSON 改写而变化，
以及“先报告成功再非零退出”不能通过探针。

本轮输出单独存放在 `metrics/vpd-architecture-review-20261031/`，避免覆盖历史性能证据。
最终测试与源码摘要见该目录的 `release_validation.json` 和 `source_manifest.json`。
仓库附有 [公开测试摘要](validation/architecture-review-20261031.json)，完整运行日志留在实验机器。
基准脚本的小样本运行只验证脚本和输出一致性，不能作为简历效果。

## 后续并发路由调整

原先覆盖完整请求的锁已改为只保护请求登记、空闲槽位选择和释放的短锁。
`StageRouter` 负责原子预留 V/P/D；V/P 在 ACK 后释放，D 在生成完成后释放。
事件泵是 worker 事件队列的唯一消费者，核对请求 ID 与 rank 后投递到各请求收件箱。
回调由请求线程执行，不阻塞事件泵；异常由单一关闭者唤醒在途请求并回收整组进程。

新增测试覆盖双 D 解码区间重叠、各请求 Token 归属、四请求排队及槽位复用、并发 SSE、
满载 429 后恢复，以及消费者失败时其他请求退出和 worker 回收。
微型模型测试中的人工 Decode 延迟只用于确定重叠窗口，不计入任何性能结论。
真实 SmolVLM 的并发冒烟另行保留输出对齐记录；当时真实四卡 NCCL 尚待测，后续实测见下节。
本轮 [公开验证摘要](validation/parallel-routing-20261031.json) 汇总 103 项单元/集成测试、41 项启动器检查及 18 条真实模型测量请求；原始记录位于 `metrics/vpd-parallel-20261031/`。

## 2026-11-01 四卡验证与缓存数值修复

租用 4×RTX4090 完成真实设备池验收后，正式混合复用负载暴露出 BF16 缓存问题：
图片种子 `[0,2019]` 的部分命中请求，三轮均出现生成 Token 不一致，HTTP 本身正常。
直接 CUDA 诊断确认，单图与双图 encoder batch 的特征最大绝对差为 0.75；
补齐原 batch 大小后，该失败样例的特征逐元素相等，Token 恢复一致。

提交 `567ecf8` 将缓存命名空间按请求图数隔离，部分命中、重复图片去重后以重复缺失图片
补齐 encoder batch，仅缓存所需结果。新增实际 encoder 槽位和补齐计数，避免把逻辑去重
当成实际节省的计算。新增三项回归，本机共 106 项单元/集成测试、41 项启动器检查通过，
3 项本机多卡用例跳过；云端四卡用例显式执行通过。

修复后拓扑 A 的两组正式基准和并发冒烟，加上拓扑 B 的四组正式基准，
共 3420 条测量请求无 Token 不一致，含 2280 条 VPD 请求逐 Token 对齐。
固定拓扑 B 的冷图无缓存、客户端并发 1→2，吞吐 23.9→44.9 Token/s（+87.5%）；
并发 1 混合复用缓存 TTFT P50 144.2→126.4ms（降低 12.3%）。完整条件见
[四卡记录](validation/four-gpu-20261101.md)。重启导致的拓扑和共享内存变化单独记录，
吞吐比例不跨拓扑计算；64MiB 共享内存引起的初始化失败在恢复 10GiB 后解决。
CUDA peer access 为 false，实际调试通道为 SHM，不称为直接 GPU P2P。
