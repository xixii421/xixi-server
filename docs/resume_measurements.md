## 围绕两个问题做对照

| 问题 | 对照配置 | 优先填写指标 | 同时记录 |
|---|---|---|---|
| NCCL 相对 CPU 中转是否改善交接？ | 相同设备池映射，Gloo vs NCCL；关闭视觉缓存，载荷校验模式相同 | 固定载荷 V→P / P→D 完整交接 P50；必要时补 E2E 或首/第二 Token 间隔 | 载荷大小、dtype、模型、GPU 拓扑、重复次数和输出一致性 |
| 视觉缓存在什么负载下有效？ | 相同设备池/NCCL，LRU 关闭 vs 开启，其余不变 | 客户端 TTFT P50；必要时补输出 token/s | 热、冷、混合图片的命中率和冷图代价；输入输出规模、并发、请求数 |
| 有界流水线怎样随负载变化？ | 同版 VPD、同四卡拓扑、客户端并发 1/2/4 | 整组墙钟有效输出 Token/s、路由等待、TTFT/E2E | 双 D 解码重叠与同 D 无自重叠；不称为单卡到四卡扩容或旧/新代码消融 |

探针完整交接包含 staging、接收校验和 ACK，不是原始链路带宽。P 产生首 Token 后才交接 KV，只看 TTFT 可能看不到 KV 开销。SSE 分块不等于模型 Token，不能把分块间隔直接写成 TBT。

## 实验条件

- 相同权重、预处理、生成长度、greedy 策略、正常 KV Cache 和请求内容。模型常驻，启动加载不计入稳态延迟。
- 默认每配置每场景 3 轮、每轮 20 请求；相同预热不计结果，保留逐请求和每轮数据。小样本 P95 仅作描述，不写生产 P99/SLO 保证。
- Gloo/NCCL 实验块当前未全局交错随机化。避免其他 GPU 任务，记录温度/频率，必要时反向顺序补跑；很小的差异不急于归因为优化。
- 性能对照可关闭完整 SHA256，但双方模式相同，并先通过开启校验的正确性验收。CPU 视觉 LRU 的上传/下载计入真实路径，不据此声称零拷贝。
- 单模型一张卡、本轮 VPD 四张卡可以比较服务延迟，不能直接写成等算力扩容效率或成本下降。吞吐为有效输出 Token / 测量墙钟时间，不能把各阶段 token/s 相加。
- 不剔除慢请求；失败计入成功率并记录原因；不能只报告 100% 命中的最好场景。
