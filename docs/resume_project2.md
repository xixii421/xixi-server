# 项目 2 简历文案

定位：**多模态服务拆分、跨阶段通信与特征复用**。项目 1 体现引擎内部 KV、调度和 GPU 执行优化，这里集中写服务边界、数据交接和复用。

## 当前可用的三条

**xixi-server | 多模态三阶段推理服务**　2026.06 - 至今

基于 ModServe 开源实现扩展，使用 PyTorch、Transformers、SmolVLM、Gloo/NCCL 与 HTTP/SSE。

- 将视觉编码、Prefill、Decode 拆为 1V+1P+2D 设备池，实现空闲槽位路由与有界并发背压；相同 4×RTX4090、SmolVLM-256M BF16、双图/8 输出 Token 的 NCCL 冷图无缓存合成负载下，客户端并发 1→2，吞吐 23.9→44.9 Token/s（提高 87.5%）。
- 实现 Gloo 元数据/ACK 与 NCCL CUDA 张量交接，打包传输多层 KV，管理特征/KV 生命周期及取消、超时、进程退出；完成 2280 条真实四卡 VPD 请求与单模型逐 Token 对齐。
- 实现内容寻址、字节级 LRU 的视觉缓存，修复 BF16 部分命中改变 encoder batch 形状导致的输出漂移；并发 1、90% 图片命中的混合复用合成负载下，TTFT P50 从 144.2ms 降至 126.4ms（降低 12.3%），并保留冷图对照。

证据绑定提交 `567ecf8`，正式配置每场景 3 轮、每轮 20 请求；另有真实四卡并发 2 的 180 条冒烟记录。
累计 2280 条为 VPD 请求数；加单模型对照共 3420 条测量请求，包含 3240 条正式测量和 180 条冒烟。
主文性能指标均采用固定拓扑 B：V/P 在 NUMA0，D2/D3 在 NUMA1；UUID/PCI 身份在测试前后保持一致。
已完成该拓扑的 NCCL 并发 1/2/4 和 Gloo 并发 2 对照。完整条件与各负载结果见
[四卡报告](validation/four-gpu-20261101.md) 和 [机器可读摘要](validation/four-gpu-20261101.json)。

## 当前实测结果的使用边界

- 吞吐比较采用同版 VPD、相同四卡布局、相同冷图无缓存负载，只改变客户端并发；不是旧串行实现与新版路由的代码消融，也不是单卡到四卡的扩容收益。
- 并发 2→4 的冷图无缓存吞吐只再提高 3.5%，而路由等待 P50 增至 332.2ms、TTFT P50 增至 456.0ms；不把提高客户端并发称为线性扩容。
- 主文使用 NCCL 并发 1 混合复用缓存结果：三轮配对 TTFT P50 降低分别为 11.6%、10.9%、12.5%，图片命中率均为 90%。
- 相同并发 1 的冷图 TTFT P50 为 144.4 → 145.4ms，约增加 0.7%；其他并发的冷图成本按报告单独列出。
- 四卡 CUDA peer access 均为 false；NCCL API 验收通过不代表 GPU 直接 P2P、NVLink、RDMA 或零拷贝。
- 单模型基线占一张卡，VPD 占四张卡，不能据此宣称等 GPU 预算的成本或扩容收益。
- encoder batch 补齐有计算成本；图片命中率、不同缺失图片数与实际 encoder 槽位数分别记录。

通信探针的“完整交接”包含 staging、接收校验和 ACK，不能改写为裸 PCIe 带宽。

## 历史结果与使用规则

- 历史单卡证据：RTX 4060 Laptop 8GB、SmolVLM-256M BF16、并发 1、双图/8 输出 Token、Gloo，100% 图片命中时 TTFT P50 为 113.3 → 58.3 ms，降低 48.5%；冷图 TTFT 增加 4.4%。见 [历史消融报告](vpd_benchmark.md)。
- 上述数字属于当时的源码与单卡条件，不能替代本轮四卡实测。

- ModServe 的论文架构、原模型适配及论文 A100 吞吐/成本结果归原作者，不能写成自己的实测成果。
- 可写有界跨请求阶段重叠、多 Decode 副本路由、真实四卡解码区间重叠及上述条件下的实测吞吐。当前不写动态批处理、同 worker 的计算通信重叠、TP、RDMA、CUDA IPC、零拷贝或生产 P99 SLO。
